# 轻量数据备份方案

本方案只保存不可重建的个人阅读成果与运行配置。源码从 GitHub 恢复；语音模型和数据目录外的原刊不打包，只记录恢复清单。与 [完整主机迁移](HOST_MIGRATION.md) 中连原刊一起复制的方式不同，这是用户选定的轻量方案。

## 备份范围

以实际应用数据目录为准，Windows 默认 `%LOCALAPPDATA%\KanduWeb`。采用「完整保留，明确排除」的方式，不仅备份名称中包含 `reading` 的文件：

| 内容 | 处理 |
| --- | --- |
| `reading_history/`、`reading-activity.sqlite3`、`reading-stats.json` | 全部保留：位置、耗时、词数采样、每日活动、已读清单、去重统计的原始记录 |
| `article_states/`、`article_tags/` | 全部保留：已读 / 未读 / 不感兴趣、主题标签 |
| `cache/` | 全部保留：解析正文、文章索引、摘要、生词表、句子讲解及旧解析迁移记录；不能将整个目录当作可删缓存 |
| `wordbook.sqlite3`、`vocab/`、`discussions/` | 全部保留：个人生词、来源、笔记及文章讨论 |
| `books.json`、`books/`、`covers/`、`podcasts/` | 全部保留：稳定的刊物和文章标识、目录内书籍、播客文字稿、转写结果、导入状态及封面 |
| 配置、访问控制、同步授权、限流和额度数据库等其余数据 | 全部保留，不丢弃原有配置；其中包含敏感凭据 |
| `models/faster-whisper/` | 排除模型缓存；记录模型名、计算设备、模型仓库和已缓存版本，保留 `podcasts/transcription.json`（如有） |
| `ecdict.db` 及其 SQLite 配套文件、建库临时文件 `ecdict.tmp` | 排除可重建词典；从源码附带的 `kandu/assets/ecdict_compact.tsv.zip` 重新建索引，不排除其他数据库 |
| 数据目录外、由 `books.json` 引用的 EPUB / PDF | 不复制原文件；记录刊物 ID、文件名、原路径、文件大小及 SHA-256，以后重新下载核对 |
| 源码、Git 历史、Python 环境、系统依赖 | 不复制；记录源码提交 ID，新机从 GitHub 取回相应版本，再安装依赖 |

**播客转写文字不等于语音模型缓存。** 已有文字稿、分段及时间戳继续备份，避免重新抓取或转写造成内容和段落变化，影响摘要、讨论、生词来源和阅读位置。

同域名接管还需单独保留很小的运行配置：`KanduWebRuntime/web-launch.json`、`cloudflared/config.yml` 和该隧道的凭据 JSON。无需复制 `cloudflared.exe`、Python `.venv`、PID、启动日志、Cloudflare 管理证书或 GitHub SSH 私钥。还原时修正路径，并按主机迁移文档先本机验证、再接管隧道。

## 体积与清单

2026-11-26 本机只读盘点：完整数据目录约 589 MiB，排除语音模型后约 125 MiB，再排除可重建词典后约 **61 MiB（未压缩）**。未计入另行省略的约 578 MiB 外部原刊。目录内书籍约 4 MiB，仍保留。数值是当时的盘点值，后续随阅读增长，不是固定上限；压缩包大小以实际导出为准。

个人资源清单保存到仓库外，例如 `%LOCALAPPDATA%\KanduWebRuntime\backups\reading-data-inventory-时间戳\`。每次实际导出时应重新盘点并将当时的资源清单放入备份包；清单中的当前源码提交 ID、文件名和校验值有助于恢复同一版本，但**清单本身不是阅读数据备份**。清单包含个人书库信息，不提交 GitHub。

## 制作与恢复要求

1. 各设备先完成待同步阅读记录；只在手机 / PWA 内、尚未上传的记录不在服务器备份中。等待生成和导入任务结束后停止 Web 写入，再制作一致快照。保留所有阅读和生成数据的数据库，不只复制统计汇总。
2. 应用数据完整打包，仅执行上述明确排除项。SQLite 使用一致性备份或停服后的完整快照，不在写入时只复制数据库主文件。资源清单随包保存；源机数据及模型、原刊均不删除。
3. 备份包在上传网盘前加密，密码另行保存；保留多个日期版本，在另一台电脑或离线介质再留一份。
4. 新机从 GitHub 获取记录的源码版本，重建运行环境，恢复数据并修正目录内书籍路径。保留原刊 ID、文章编号和缓存目录，不靠重新上传创建新条目来恢复阅读轨迹。
5. 按清单重新下载外部原刊，核对大小与 SHA-256，再修正 `books.json` 的原路径。文件名相同不能保证内容相同；缺少原刊时可能仍能查看已有正文缓存，但原文件下载或需要重解析的功能尚不可用。此方案接受以后无法重新下载原刊的风险。
6. 本地词典在首次查询时从源码资源自动建库；仅再次转写新音频时才需要安装转写依赖、重新下载语音模型，浏览已有播客文字稿不要求模型。
7. 验证书库索引、阅读位置、已读状态、日历及计时、生词本、摘要、讲解和讨论均已保留，再按主机迁移文档接管原域名。同一时刻仍只运行一套提供写入服务的数据。

本文确定备份范围和恢复约束，当前没有自动执行上述流程的导出 / 恢复脚本。本次资源盘点也不代表已制作可恢复的备份包。
